# 建模方法论手册

> 本文是通用建模规范与已核对案例的整理，不是对 145 篇论文的频率统计。具体案例见 [EVIDENCE_CASES](EVIDENCE_CASES.md)。

## 1. 先建立“任务契约”

对每一问先写清：

```text
给定什么
→ 要求输出什么
→ 可以控制什么
→ 必须满足什么
→ 用什么标准评价
```

任务动词比题目背景更能揭示数学结构：预测、分类、估计、评价、排序、调度、规划、解释和决策对应不同的输出与证据。

注意边界：未来风险不一定是普通监督预测，也可能是情景推演；“最短路径”不一定天然是图问题，也可能包含连续空间、动力学或时变约束。

## 2. 让各问形成技术链

优先寻找问题之间的输入输出关系：

```text
原始数据
→ 特征或指标
→ 参数或状态
→ 预测或评价
→ 优化或决策
```

串联时必须记录误差传播。若前一问输出作为后一问参数，可使用置信区间、扰动场景、Monte Carlo 或鲁棒优化评估其影响。

各问不应为了“统一”而强行使用同一种模型；共享的是信息和逻辑，不一定是算法。

## 3. 把自然语言操作化

抽象概念不能直接送进 AHP、TOPSIS 或神经网络。先完成：

```text
概念定义
→ 子维度
→ 可观察量
→ 指标与方向
→ 标准化/映射
→ 综合量
→ 敏感性与解释
```

每个指标都要回答：它为什么代表该概念、是否重复、是否可测、量纲如何处理。指标数量不是质量标准。

## 4. 用 baseline 管理模型复杂度

推荐顺序：

```text
最简单可信模型
→ 找出具体缺陷
→ 针对缺陷增加复杂度
→ 同条件比较
→ 判断收益是否值得
```

baseline 可以是朴素规则、经典机理方程、线性模型、原方案或成熟求解器。复杂模型没有同条件对手时，只能说明“跑出了结果”，很难说明改进价值。

## 5. 模型选择理由写成因果链

不要写“随机森林效果好”或“遗传算法全局搜索能力强”。应写：

```text
问题具有某种结构或困难
→ 简单方法在哪一步不足
→ 候选模型提供什么能力
→ 增加了哪些假设和成本
→ 如何验证新增能力
```

模型选择至少考虑数据量、变量类型、非线性、时间/空间/分组结构、约束、可解释性、计算预算和评价指标。

## 6. 机理与数据驱动不是二选一

机理模型适合规律、参数和边界条件足够明确的场景；若关键参数不可辨识、简化假设过强，机理模型也可能产生虚假确定性。

数据模型适合复杂映射和高维交互，但需要足够样本、严格划分和泛化验证。组合路线可以是：

- 机理模型提供结构，数据估计参数；
- 机理模型作 baseline，数据模型学习残差；
- 物理约束进入损失函数或可行域；
- 数据模型筛选场景，机理模型完成决策。

## 7. 数据处理属于模型

必须记录数据来源、单位、缺失、异常、重采样、时间/空间对齐、对象分组、标准化和划分方式。

防止泄漏：标准化、插补、特征选择和超参数调节都只能在训练折内拟合；同一对象、设备、时间段或相邻窗口不应无意跨越训练与测试边界。

## 8. 特征工程遵循三项标准

- 判别或预测能力；
- 非冗余；
- 领域可解释性。

相关系数、互信息、PCA、模型重要性和消融只是工具。特征筛选必须嵌套在训练过程内，不能偷看测试集。

## 9. 组合模型必须职责清楚

为每个模块填写四项：解决的困难、输入、输出、验证。删除模块后若没有失去明确能力，该模块可能只是装饰。

好的组合模型是功能链，不是算法名清单。

## 10. 优化先写模型，再写算法

先明确决策变量、目标、约束和可行域，再判断线性、凸性、整数性、可分解性和规模。能用成熟数学规划求解时，不应仅因熟悉而改用启发式算法。

使用启发式算法时应报告可行性、多个随机种子、收敛、计算预算和基准方案。算法找到的是搜索结果，不自动等于理论全局最优。

多目标加权求和并非不可用，但要说明目标是否可补偿、尺度如何统一、权重来源及敏感性。目标明显冲突时，可考虑 Pareto、ε-constraint 或分层优化。

## 11. 模型成立需要证据链

```text
数学与单位正确
→ 数据与划分可信
→ 指标与任务匹配
→ 基线比较公平
→ 稳定性/鲁棒性/泛化检查
→ 机理和现实解释
→ 有边界的结论
```

计算结果、拟合优度或单次高准确率都不足以单独证明模型可靠。

## 12. 最小可信模型

比赛时间有限时，优先保证：

- 定义合理；
- 公式和单位清楚；
- 结果可复现；
- 有可比较的 baseline；
- 有与任务匹配的验证；
- 结论能够解释并限定范围。

复杂度只有换来明确、可验证的能力时才有价值。
