# 数模论文写作指南

> 写作不是把计算过程搬进文档，而是呈现“问题—模型—算法—结果—证据”的可复核链条。

## 总体结构

建议以“摘要 → 问题重述 → 问题分析 → 假设 → 符号 → 数据预处理 → 各问的分析/建模/求解/结果/验证 → 模型评价与推广 → 结论 → 参考文献 → 附录”组织。各问不必套同一模板，但必须闭环。

## 摘要

- 背景与核心困难 1—2 句；
- 总体方案 1 句；
- 每问写“难点 + 方法 + 关键定量结果”；
- 最后给总体结论、适用条件或主要限制。

不要只写“效果良好”；给出指标、对照、条件和单位。

## 问题重述

用自己的结构说明“给定什么、求什么、限制什么、输出什么”，不逐句抄题，不提前加入尚未论证的模型假设。

## 问题分析

每问回答：任务类型是什么；难点在哪里；为何不能直接算；如何拆步；为何选择这条路线；和前后问如何连接。把模型选择写成因果链，而非算法名清单。

## 模型假设

每条假设要说明简化了什么、进入哪条公式、可能带来什么偏差。不要写“假设数据真实可靠”等无操作意义的万能句。

## 符号说明

定义核心变量、参数、集合、单位和下标；同一符号全文含义一致。局部符号可在公式附近解释，避免堆出过长但无人使用的符号表。

## 数据预处理

说明数据来源、字段与单位、缺失/异常规则、对齐、重采样、标准化、降噪和划分。写清阈值与参数依据；训练侧拟合的变换不能泄漏验证/测试信息。

## 模型建立

先解释现实含义，再给变量、目标/方程与约束，随后解释每一项和参数来源。公式前回答“为什么建”，公式后回答“各项代表什么、如何求”。

## 模型求解

交代算法选择与模型结构的对应关系、初始化、终止条件、软件/求解器、关键参数、随机种子和计算预算。区分模型本身与求解模型的算法。

## 结果分析

按“结果 → 对比 → 误差/不确定性 → 现实含义 → 适用边界”写。表格给精确数值，图展示趋势与差异；正文解释证据，不复述所有数字。

## 模型验证

说明数据划分、baseline、公平比较条件、任务指标、稳定性/鲁棒性/泛化性、消融与机理一致性。把验证放在关键结论附近，不只在文末笼统评价。

## 模型评价

- **优点**必须对应已展示证据；
- **局限**说明数据、假设、计算量、可解释性或外推边界；
- **改进方向**应针对局限，不写空泛的“提高精度”。

## 推广

明确哪些结构可迁移、哪些参数需重估、需要哪些新数据以及失效条件。不能因为在一个题目上有效就声称适用于所有同类问题。

## 结论

逐问直接回答赛题要求，给关键数值、条件和决策含义；不在结论中首次引入新方法或新结果。结论强度与正文证据一致。

## 附录

放置影响复现但会打断正文的内容：核心代码、补充推导、参数表、额外结果和数据字典。正文必须引用附录位置；附录不能替代必要的方法说明。

## 严谨语言规范

| 词语 | 可以使用的条件 | 证据不足时建议表达 |
|---|---|---|
| 显著 | 预先说明统计检验、显著性水平、效应量与样本条件 | 明显、较大、在当前样本中观察到 |
| 最优 | 已证明全局最优，或明确限定为候选集/搜索预算内最优 | 当前候选中最好、搜索到的最好解 |
| 证明 | 有严格推导、定理或充分实验设计支持相应命题 | 表明、支持、提示、与……一致 |
| 泛化 | 在独立对象、时间、区域或工况上验证 | 在当前测试集有效，跨场景仍待验证 |
| 鲁棒 | 对明确范围的噪声、缺失、参数或场景扰动测试 | 在所测试扰动范围内较稳定 |
| 准确 | 有参考真值、误差指标、数据划分和不确定性 | 拟合误差较低、与参考值较接近 |
| 有效 | 明确任务、基线、指标与适用范围，并有对照证据 | 在当前设置下改善了……指标 |
| 优越 | 在公平条件下对多个合理对手持续占优，并说明代价 | 在……指标上优于所比较的模型 |

## 图表与公式

- 图名、表名、坐标、单位、图例和样本范围完整；
- 图表编号按引用顺序，正文必须解释其论证作用；
- 公式变量首次出现即定义，量纲和边界可检查；
- 避免三维装饰图、难辨配色、截图式表格和无来源数据。

## 交稿前检查

- [ ] 摘要包含各问方法与定量结果。
- [ ] 术语、符号、单位、数据版本前后一致。
- [ ] 每个复杂模块都有选择理由、baseline 或消融证据。
- [ ] 图表与正文数字一致，结果可由代码复现。
- [ ] “显著、最优、证明、泛化、鲁棒、准确、有效、优越”均未超过证据。
- [ ] 公式、复杂表格和图像已回看原始 PDF 或原始计算结果。
