# 数模论文写作指南

> 写作的任务是呈现可复核的推理链，不是给算法做宣传。

## 总体原则

```text
结论
← 证据
← 指标
← 实验、计算或推导
← 明确的模型与数据
```

每一问尽量形成“分析—建模—求解—结果—验证”的局部闭环，并交代其输出如何进入下一问。

## 摘要

推荐顺序：核心困难与总体路线 → 各问的方法和关键定量结果 → 总结与适用范围 → 关键词。

摘要不是目录，也不是背景综述。每问至少写“针对什么困难、建立什么模型、得到什么关键结果”。没有指标时不要用“准确、优秀、显著”等评价词。

## 问题重述

用“给定—约束—要求—输出”重构任务，不复制题面。读者应能据此理解数学对象和最终交付物。

## 问题分析

回答六件事：任务本质、主要困难、为什么不能直接计算、拆成哪些步骤、为什么选这种模型、与前后问题如何衔接。

弱表达：

> 本题较复杂，因此采用随机森林。

更严谨：

> 目标与输入存在非线性交互且缺乏明确解析关系。先以线性模型检验简单关系，再使用能够表达非线性交互的随机森林；两者在相同分组交叉验证下比较，并以特征重要性辅助解释。

## 模型假设

每个假设都应说明它简化了什么、进入哪个公式或约束，以及可能带来什么偏差。不要重复题目事实，也不要写“计算机正常运行”之类无效假设。

## 符号、变量与公式

符号说明至少包含含义、单位和必要的取值范围。公式前交代来源和动机，公式后解释每一项、参数来源和适用条件。

## 求解过程

说明算法、参数、初始化、停止条件、随机种子、软件与必要的计算预算。若用近似或启发式方法，应说明可行性检查和重复运行。

## 结果分析

按四层展开：结果是什么 → 与 baseline/原方案相比如何 → 为什么会这样 → 现实中意味着什么。图表是证据，不应只写“如图所示”。

## 验证与评价

区分拟合、预测、稳定、鲁棒、泛化和机理一致性。模型评价同时写优点、限制与适用条件，不要列空泛优点。

## 结论强度词典

| 避免直接写 | 有证据时可写 |
|---|---|
| 模型非常准确 | 测试集 RMSE 为……，较 baseline 下降……% |
| 算法显著优于 | 在相同划分和指标下，差异为……；统计显著性需给检验和效应量 |
| 证明模型正确 | 结果在当前数据和测试条件下支持该模型 |
| 得到最优方案 | 在比较的候选方案/搜索预算内取得最低目标值 |
| 泛化能力很强 | 在未参与训练的场景中性能下降……%，表明在该范围内具有一定泛化能力 |
| A 导致 B | A 与 B 在当前数据中相关；因果结论需要额外设计 |

## “显著、最优、证明”

- “显著”最好有统计检验、比较条件和效应量；
- “最优”必须区分全局、局部、候选方案中和当前搜索得到的最好值；
- “证明”用于数学证明，数据实验通常写“验证、支持、表明”。

## 图表

标题、单位、图例和样本范围完整。正文指出主要变化、比较幅度及其支持的结论。避免用颜色代替所有信息，关键结果应可由表格或文字复核。

## 摘要与正文检查表

- [ ] 摘要有总体路线、各问方法和关键结果；
- [ ] 问题分析说明“为什么”；
- [ ] 变量、单位、参数来源明确；
- [ ] 公式前有动机、后有解释；
- [ ] 结果有 baseline、对比和现实含义；
- [ ] 图表真正参与论证；
- [ ] 结论没有超出数据、场景和验证范围；
- [ ] 局限性真实，推广说明适用条件。
