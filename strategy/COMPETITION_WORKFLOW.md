# 数学建模比赛十阶段工作流

> 每个阶段都应留下可交接产物。模型、代码、图表和正文同步推进，避免最后集中补证据。

## 阶段 1：审题

- 列出每问的输入、输出、任务动词、约束、评价标准和交付格式。
- 标出题目原话、团队解释和待确认假设，形成“任务契约”。

## 阶段 2：数据检查

- 核对字段、单位、缺失、异常、重复、时间/空间粒度、标签与样本独立性。
- 确定训练/验证/测试或前向/分组划分，所有预处理只在训练侧拟合。

## 阶段 3：题型判断

- 将背景映射到预测、分类、评价、优化、机理、图或不确定性等结构。
- 明确各问依赖关系、上游输出和潜在误差传播。

## 阶段 4：建立 baseline

- 选最简单、可复现、可解释的规则/模型作为对照。
- 统一数据、指标、预算和随机种子，记录 baseline 的缺陷而不只记录分数。

## 阶段 5：模型改进

- 每个新增模块必须对应 baseline 的一个明确缺陷。
- 先确定模型与假设，再选求解算法；复杂模块预留消融和解释方案。

## 阶段 6：求解与实现

- 固定数据版本、参数、随机种子和环境；保存中间结果与日志。
- 检查单位、约束、收敛、边界、数值稳定性和可重复运行。

## 阶段 7：验证

- 同条件比较 baseline；按任务报告匹配指标和误差分布。
- 做稳定性、鲁棒性、泛化性、消融、机理/现实一致性及上游误差传播检查。

## 阶段 8：可解释性

- 优先解释结构、参数和机理，再使用 SHAP、PDP、LIME、注意力等工具。
- 明确解释对象、样本范围和边界，不把关联贡献写成因果证明。

## 阶段 9：写作

- 每问形成“分析 → 建模 → 求解 → 结果 → 验证 → 小结”闭环。
- 图表服务论证；摘要给出难点、方法、关键定量结果和适用条件。

## 阶段 10：最终检查

- 从题目要求反向核对所有输出；重跑核心代码并复核表格、图、单位、编号和引用。
- 检查模型名是否由正文支持、结论强度是否超过证据、附录能否复现关键步骤。

## 每问提交前检查表

- [ ] 输入、输出、变量、单位与约束已定义。
- [ ] 方法选择对应明确困难，并有简单 baseline。
- [ ] 数据处理无泄漏；代码和参数可复现。
- [ ] 结果包含数值、对比、误差/区间和现实解释。
- [ ] 解满足全部约束，异常与失败样本已分析。
- [ ] 与前后问的接口和误差传播已说明。
- [ ] 小结直接回答赛题要求，没有夸大。

## 摘要检查表

- [ ] 用 1—2 句交代核心任务与困难，而非大段背景。
- [ ] 每问都有“难点 + 方法 + 关键结果”。
- [ ] 关键指标带数值、比较条件和单位。
- [ ] 没有只写“效果良好、科学合理”等空泛判断。
- [ ] 总结适用范围、主要优势及必要限制。
- [ ] 关键词与正文术语一致。

## 建模可信性检查表

- [ ] 数学：量纲、边界、约束、极限情况正确。
- [ ] 数据：来源、代表性、划分、缺失和异常处理可追溯。
- [ ] 数值：指标与任务匹配，误差分布和不确定性已报告。
- [ ] 对比：baseline 与复杂模型同数据、同指标、同预算。
- [ ] 稳定：种子、参数、采样或初值变化不会造成未解释的剧烈变化。
- [ ] 鲁棒：噪声、缺失或场景扰动下性能/可行性可接受。
- [ ] 泛化：未见对象、时间、区域或工况有独立证据，或已明确未验证。
- [ ] 解释：结构与机理说得通，工具解释不冒充因果。
