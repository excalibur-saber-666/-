# 数学建模比赛工作流

> 目标是尽快形成“最小可信模型”，再用剩余时间做有针对性的改进。

## 1. 审题与任务契约

逐问记录任务动词、输入、输出、约束、评价标准、数据来源和与其他问题的接口。不要在这一步先写算法名。

## 2. 数据与机理勘察

- 检查缺失、异常、重复、单位、时间/空间/对象分组；
- 建立最小可复现的数据处理脚本；
- 查找守恒、几何、动力学或领域经验关系；
- 提前确定训练、验证和测试边界，防止泄漏。

## 3. 建立 baseline

先完成一个定义清楚、可运行、有解释的简单方案。baseline 用于暴露困难，也用于证明后续复杂度是否值得。

## 4. 针对缺陷改进

每次增加模块都记录：解决的缺陷、输入、输出、额外假设、验证方法。无法回答这些问题的模块暂不加入。

## 5. 验证与压力测试

至少完成精度或目标值、基线对比、约束检查和稳定性；核心模型再增加鲁棒性、泛化、消融或不确定性传播。

## 6. 同步写作

每得到一个结果，立即保存数据版本、参数、图表、结论和限制。正文按“分析—模型—求解—结果—验证”的局部闭环推进。

## 提交前检查

### 模型

- [ ] 输入、输出、变量、单位和约束明确；
- [ ] 模型选择理由对应具体困难；
- [ ] 复杂模型有 baseline；
- [ ] 所有输出重新检查可行性和边界；
- [ ] 随机种子、关键参数和软件版本有记录。

### 证据

- [ ] 评价指标与任务匹配；
- [ ] 训练、验证、测试无明显泄漏；
- [ ] 比较使用相同数据划分和指标；
- [ ] 结果有稳定性或敏感性检查；
- [ ] 结论强度不超过证据范围。

### 写作

- [ ] 摘要给出方法和关键定量结果；
- [ ] 每个公式前有动机，后有变量解释；
- [ ] 图表在正文中被解释；
- [ ] “显著、最优、证明”等词有相应证据；
- [ ] 结论回答题目且说明适用范围。
